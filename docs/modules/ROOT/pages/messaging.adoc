= Messaging Setup (Discord & Telegram)
:page-title: Messaging Setup
:page-description: Configure the Discord and Telegram adapters, with voice, shared context, and message chunking

Qlawkus includes messaging adapters for Discord and Telegram with voice support. Slack and WhatsApp adapters exist but are not wired into the default `app/` module (only `qlawkus-messaging`, `qlawkus-messaging-discord`, and `qlawkus-messaging-telegram` are).

== Conversation context

When you chat with the agent via any channel (REST, Discord, Telegram), it keeps a working memory of the back-and-forth conversation. Two knobs govern that context, both on the `qlawkus.agent` root:

*Shared context (default on).* All channels share the same conversation, so the agent stays continuous across Discord, Telegram, and REST (the owner is one person regardless of channel). Disable it to give each channel its own conversation:

[source,bash]
----
export QLAWKUS_AGENT_SHARED_CONTEXT_ENABLED=false
----

*Idle reset (default 60 minutes).* If a conversation is idle for longer than the configured window, the working memory is cleared before the next message so stale context does not accumulate. Set the window to `0` to disable:

[source,bash]
----
export QLAWKUS_AGENT_CONTEXT_TTL_MINUTES=60
----

You can also ask the agent to clear the context at any time. Say things like "clear the context", "reset", "start over", "new topic", or "forget our conversation", and the agent wipes the short-term conversation and starts fresh on the next message. This does *not* erase long-term saved facts about you; only the running back-and-forth is cleared.

== Discord Bot

=== 1. Create a Discord Application

1. Go to https://discord.com/developers/applications
2. Click *New Application* > name it (e.g., "Qlawkus")
3. Go to *Bot* tab > *Add Bot*
4. *Public Bot:* Leave unchecked if only you will use it. When checked, anyone can install the bot.
5. Under *Privileged Gateway Intents*, enable *Message Content Intent* (required for the bot to read messages). Without this, the bot cannot see message text.
6. Go to *OAuth2* > *General* > copy *Application ID*

=== 2. Configure Permissions & Invite

1. Go to *OAuth2* > *URL Generator*
2. Scopes: `bot` + `applications.commands`
3. Bot Permissions:
   * Send Messages
   * Read Messages / View Channels
   * Read Message History
   * Use Slash Commands
   * Attach Files (for voice messages, sent as file attachments)
4. Copy the generated URL, open in browser, and invite to your server

=== 3. Environment Variables

[source,bash]
----
export QLAWKUS_MESSAGING_DISCORD_BOT_TOKEN=your-bot-token
export QLAWKUS_MESSAGING_DISCORD_APPLICATION_ID=your-application-id
export QLAWKUS_MESSAGING_DISCORD_GUILD_ID=optional-guild-id-for-faster-command-sync
export QLAWKUS_MESSAGING_DISCORD_STARTUP_CHANNEL_ID=optional-channel-id-for-startup-message
export QLAWKUS_MESSAGING_DISCORD_RESPOND_TO_ALL_MESSAGES=true
export QLAWKUS_MESSAGING_DISCORD_STARTUP_GREETING="👋 Qlawkus online and listening"
export QLAWKUS_MESSAGING_DISCORD_RESPOND_TO_DIRECT_MESSAGES=true
----

Channels and direct messages are gated separately, both defaulting to `true`. Setting
`QLAWKUS_MESSAGING_DISCORD_RESPOND_TO_ALL_MESSAGES=false` keeps the bot quiet in guild channels while
DMs and slash commands still work; `QLAWKUS_MESSAGING_DISCORD_RESPOND_TO_DIRECT_MESSAGES=false` does
the reverse. Set both to `false` to leave only slash commands. They are separate knobs because going
quiet in a shared server is a common ask, while the owner's DM is the private line to the agent - one
should not silence the other.

Auth (who may talk to the bot). The allowlist denies by default: until you list at least one user ID, the bot rejects every message and logs a warning at startup naming the channel.

[source,bash]
----
export QLAWKUS_MESSAGING_AUTH_ALLOWED_USERS_DISCORD=123456789
# or comma-separated user IDs: 123456789,987654321
----

To find your ID, enable Developer Mode in Discord (User Settings, Advanced), then right-click your name and choose Copy User ID.

`*` lets anyone who can reach the bot talk to the agent. Use it only for a throwaway bot. An unset or empty list rejects everyone.

=== 4. Slash Commands

The bot registers a `/qlawkus` command with subcommands:

* `/qlawkus ask question:<text>` - ask the agent a question
* `/qlawkus status` - health check
* `/qlawkus help` - usage info

If you set `QLAWKUS_MESSAGING_DISCORD_GUILD_ID`, commands sync instantly to that guild. Without it, global sync can take up to 1 hour.

== Telegram Bot

=== 1. Create a Telegram Bot

1. Open Telegram and message @BotFather
2. Send `/newbot` and follow the prompts
3. Copy the *Token*

=== 2. Choose Mode: Polling vs Webhook

* *Polling* (default, simpler): Bot pulls updates. Works behind NAT, no public URL needed.
* *Webhook*: Telegram pushes updates to your HTTPS endpoint. Requires a public HTTPS URL.

=== 3. Environment Variables

Polling (default):

[source,bash]
----
export QLAWKUS_MESSAGING_TELEGRAM_BOT_TOKEN=your-bot-token
export QLAWKUS_MESSAGING_TELEGRAM_MODE=polling
export QLAWKUS_MESSAGING_AUTH_ALLOWED_USERS_TELEGRAM=123456789
# or comma-separated user IDs: 123456789,987654321
----

Webhook:

[source,bash]
----
export QLAWKUS_MESSAGING_TELEGRAM_BOT_TOKEN=your-bot-token
export QLAWKUS_MESSAGING_TELEGRAM_MODE=webhook
export QLAWKUS_MESSAGING_TELEGRAM_WEBHOOK_URL=https://yourdomain.com/api/webhook/telegram
export QLAWKUS_MESSAGING_AUTH_ALLOWED_USERS_TELEGRAM=123456789
----

The allowlist denies by default, as on Discord: an unset or empty list rejects everyone, and `*` allows
anyone (use it only for a throwaway bot). To find your numeric ID, message @userinfobot on Telegram; it
replies with your ID.

After you change `.env`, recreate the app container: `./run.sh prod restart` recreates the app service.
A plain `docker compose restart` reuses the existing container and does not re-read the environment.

The webhook path is `/api/webhook/telegram` (the Slack and WhatsApp adapters, when enabled, use `/api/webhook/slack` and `/api/webhook/whatsapp`).

== Voice Support

Voice messages are supported on both Discord and Telegram via file attachments (the bot does not join voice channels). When a user sends a voice message:

1. The audio attachment is downloaded
2. The audio is transcribed via STT (OpenAI-compatible Whisper, e.g. Groq or OpenAI)
3. The agent processes the text
4. If TTS is configured, the agent can reply with voice (sent as an audio file attachment)

A voice reply can be triggered two ways, and they reinforce each other:

* *The agent calls `respondWithVoice`.* Its system prompt tells it to do so whenever you ask for audio (phrases like "responde em audio", "me manda por voz", "reply by voice"), passing the language code of the reply.
* *The orchestrator detects voice intent in your text first.* Before the agent even runs, an incoming message matching a voice-intent pattern ("manda audio", "reply by voice", "me responde por voz", in English or Portuguese) pre-arms a voice reply in the configured `TTS_DEFAULT_LANGUAGE`. The agent can still override the language by calling the tool.

The second path is why voice works even when the model forgets the tool - the same "don't depend on the model remembering" discipline the memory subsystem follows. Both paths need `TTS_ENABLED=true`; otherwise the request is logged and answered as text.

For STT/TTS setup, see xref:voice.adoc[Voice Setup].

== Message Chunking

Long responses are automatically split to fit each platform's limit:

[cols="1,1",options="header"]
|===
|Platform |Max message length

|Telegram |4,096 chars
|Discord |2,000 chars
|Slack |40,000 chars
|WhatsApp |65,536 chars
|===

== Tool Progress

While a turn runs, Discord and Telegram show what the agent is doing in one status message that is edited in place. The status message is posted at the first tool call, so a turn that uses no tool shows nothing extra:

----
📊 queryMetrics: rate(qlawkus_tool_calls_total[1h]) (0.4s)
🔎 webSearch (1.2s)
----

When the reply arrives, the status message becomes a one-line summary such as `2 tools, 1.6s`, or is deleted. The reply itself is an ordinary message and is delivered as before.

Each line has a category emoji (shell, search, telemetry, calendar, mail, files, memory, or a default), the tool name, a detail and the duration. A line appears when the model asks for a tool and is completed when that tool returns. Tool results are never shown.

[cols="1,3",options="header"]
|===
|Setting |Effect

|`qlawkus.messaging.tool-progress.mode`
|`off` posts nothing; `status` shows the tool name; `preview` (default) adds the first 40 characters of the arguments; `verbose` adds up to 300.

|`qlawkus.messaging.tool-progress.on-complete`
|`summary` (default) edits the status message to a summary line; `delete` removes it.

|`qlawkus.messaging.tool-progress.max-lines`
|Lines kept in the status message (default 6). Older calls scroll off and a `+K earlier` line keeps the count.
|===

The arguments shown are passed through the same secret redaction as the console, so a token in a tool call is masked before it reaches the chat.

Edits are throttled to at most one per second per chat. A change that arrives inside that window is not sent alone: the next tool event or the completion carries the latest state. If the platform rejects a post or an edit, progress stops for that turn, a single warning is logged, and the reply is still delivered.

=== Changing the mode per chat

Send `/verbose` in a chat (or `/qlawkus verbose` on Discord) to cycle that chat's mode through `off`, `status`, `preview` and `verbose`. The agent replies with the new mode. The change is kept in memory for that chat only: it is not written to configuration and it resets when the process restarts.

Tool progress is shown on Discord and Telegram only. Slack and WhatsApp receive the reply without a status message.

== Troubleshooting

[cols="1,3",options="header"]
|===
|Issue |Solution

|Discord bot connects but doesn't respond |Message Content Intent not enabled in Developer Portal.
|Slash commands not appearing |Wait up to 1 hour for global sync, or set `QLAWKUS_MESSAGING_DISCORD_GUILD_ID` for instant guild sync.
|Telegram webhook not receiving updates |Verify the HTTPS URL is reachable and ends in `/api/webhook/telegram`; check logs for `setWebhook` errors.
|Voice not working |Check STT/TTS config in xref:voice.adoc[Voice Setup].
|===

See xref:config-reference.adoc[Configuration] for all messaging-related environment variables.
